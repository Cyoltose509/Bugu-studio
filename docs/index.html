① 产品需求文档 (PRD) 核心

定位：社团作品档案馆 + 对外门户网站。不是下载站、不是社交平台、不是网盘。

历史保存

将分散在 Steam/GitHub/网盘的作品归档至统一数据库，形成传承资产。

对外展示

迎新宣传权威入口，展示社团历年实力与文化积淀。

传承交接

每届社长可平滑交接，持续运营5年以上，标准化运维文档支持。

② 系统架构

5 层架构：客户端 → API → 业务逻辑 → 数据/存储 → 部署基础设施。

客户端层

Next.js 14 TypeScript TailwindCSS Auth.js

App Router + Server Components，SSG/SSR 按页面需求选择。作品库列表 SSR（含筛选参数），详情页 ISR（60s 缓存）。

API 层（Next.js API Routes）

RBAC 中间件 Rate Limiter Audit Logger Zod Validator

所有请求先过中间件链：认证校验 → 权限校验 → 限流 → 输入验证 → 业务处理 → 审计记录。

业务逻辑层（Service Layer）

ProjectService UserService ReviewService StorageService

独立 Service 类封装业务规则，API Route 只做参数解析和响应格式化，不含业务逻辑。

数据层

PostgreSQL 15 Prisma ORM

全部通过 Prisma Client 参数化查询，禁止原始 SQL 拼接。关键表建立复合索引支持多维筛选。

文件存储层

Cloudflare R2 CDN 分发 预签名 URL

客户端直传 R2（不经过应用服务器），通过预签名 URL 控制上传权限。只存封面/截图/头像，游戏本体走外链。

部署层（Docker Compose）

app 容器 postgres 容器 nginx 容器 backup 容器

postgres 容器仅在内部网络暴露，对外只有 nginx 80/443 端口。backup 容器每日凌晨 3 点自动备份。

⑤ 权限模型（RBAC）

5个角色，数据库驱动权限配置，支持运营期间动态调整而无需改代码。

角色说明

Guest浏览公开内容，无需登录
User注册用户，完善个人资料
Member社团成员，需管理员手动审批授予
Reviewer审核员，审核作品和资料变更

⑥ 安全设计方案 OWASP Top 10

登录安全

  • Argon2id 哈希密码（64MB 内存，3次迭代）
  • 邮箱验证（32字节随机 token，24h 有效）
  • 登录限流：5次/账号 + 10次/IP（15分钟窗口）
  • Session 存数据库，支持主动吊销
  • Cookie: HttpOnly + Secure + SameSite=Lax

XSS 防护

  • React 默认转义 JSX 内容
  • dangerouslySetInnerHTML 前必须 DOMPurify.sanitize
  • Markdown 渲染：marked + DOMPurify 白名单标签
  • Content Security Policy (CSP) Headers
  • 禁止 script/object/embed 等危险标签

SQL 注入防护

  • 全部使用 Prisma 参数化查询
  • 禁止 $queryRawUnsafe
  • ESLint eslint-plugin-security 检测拼接 SQL
  • 代码审查强制检查项

文件上传安全

  • 白名单 MIME 类型：jpeg / png / webp
  • 文件大小限制：最大 5MB
  • 随机 UUID 文件名（防路径猜测）
  • 预签名 URL 直传 R2（不经服务器）
  • R2 Bucket 禁止目录列表
  • 禁止上传 .html/.js/.php 可执行文件

API 安全

  • 全局 Rate Limit（LRU Cache sliding window）
  • 所有写操作记录 AuditLog
  • 越权尝试记录 + 告警
  • 安全 HTTP Headers（HSTS / X-Frame-Options）
  • Origin 校验防 CSRF

环境变量安全

  • .env* 全部加入 .gitignore
  • NEXTAUTH_SECRET 每学期轮换
  • 生产环境通过服务器环境变量注入
  • 代码中无任何硬编码密钥

⑧ Docker 部署方案

容器组成

appNext.js 应用，非 root 用户运行，内存限 512M
postgresPostgreSQL 15 Alpine，仅 internal 网络可达
nginx反向代理，SSL 终止，静态资源缓存
backup每日凌晨 3 点 pg_dump + gzip，保留 30 天

部署操作

# 首次部署 cp .env.example .env.production docker compose build docker compose up -d docker compose exec app npx prisma db seed # 日常更新 git pull origin main docker compose up -d --no-deps --build app # 健康检查 curl http://localhost/api/health
安全设计： postgres 容器仅在 docker internal 网络内部可达，对公网完全隔离。nginx 是唯一的流量入口（80/443），所有 API 请求通过 X-Forwarded-For 传递真实 IP 用于限流。

⑨ 数据备份方案

每日全量

凌晨 3:00 自动 pg_dump + gzip，保留 30 天

每 6 小时

增量备份，保留 7 天（V2 后启用）

R2 文件

Cloudflare R2 自动多副本冗余，无需额外备份

代码

Git + GitHub 永久保存所有历史

恢复流程

确定目标备份文件
→
停止 app 容器（可选）
→
gunzip | psql 恢复
→
验证数据完整性
→
重启 app 容器
→
prisma migrate deploy
每学期必须执行一次恢复演练：从备份文件恢复到隔离测试环境，验证数据完整性和应用正常启动。不做演练的备份等于没有备份。

关键决策记录

决策原因
V1 不做用户注册优先完成数据录入，快速上线迎新，减少 V1 复杂度
文件不托管在服务器R2 零出口费用 + CDN，外链策略可持续 5 年以上
数据库 Session（非 JWT）支持主动吊销 Session，换届时可强制下线旧账号
Docker Compose 而非 K8s大学社团运维能力有限，Compose 够用且交接成本低
PostgreSQL 而非 MySQL更好的 JSON 支持、全文搜索、ENUM 类型、Prisma 生态
预签名 URL 上传文件直达 R2，减轻服务器带宽，服务器无需处理大文件
